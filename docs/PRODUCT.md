# Sendtry Computer: product and design

## Purpose and brand

Give an existing personal/coding agent a dedicated computer, let its owner see
and control that same screen, and teach procedures the agent can reuse.
**Sendtry Computer** is the product name. `computer-mcp` remains the technical
repository/CLI. David's Sendtry identity provides the mark, warm paper canvas,
white surfaces, salmon actions and ink text. This product has its own runtime and
data; Sendtry's delivery backend and Piblo's bot/billing layers are not dependencies.

The intended future distribution is open source under Sendtry. Today this is a
private preview, with `private: true` and `UNLICENSED`. Code license, dependency
notices, trademark/brand asset terms, public packaging and release policy remain
pending. Brand ownership is separate from a future permission to redistribute
code/assets.

## Experience

The console has five working views:

| View          | Owner's job                                                                           |
| ------------- | ------------------------------------------------------------------------------------- |
| Computer      | Watch the real guest screen, take/release control and open the offline practice task  |
| Files         | Browse the contained workspace and read/save bounded text files                       |
| Terminal      | Execute a focused guest command and inspect its output/deadline                       |
| Skills        | Teach, search, review and export a completed procedure                                |
| Connect agent | Choose work/read access, copy exact MCP configuration and download the operator skill |

The flow is **create computer → connect agent → work together → teach a task →
review → reuse**. MCP tools are capabilities. Skills are procedural instructions.
A taught skill depends on those capabilities and its owning computer; exporting
it does not create a new permission, install anything, or blindly replay actions.

Control is always visible. No lease means ready to work; an agent/human lease
shows who controls mutations. The owner's explicit Take control action revokes
agent work. View-only remains useful while the agent works. Recording starts only
with owner control; a persistent recording bar returns to review/save. The saved
skill lists missing parameters and supports a reviewed `SKILL.md` download.

Onboarding uses the exact host paths generated by the trusted CLI. They travel
only to its owner session and are never exposed by agent credentials. No API
keys appear in copy/download output. The console reports actual guest capabilities
and lease state; it does not claim that a specific harness is connected.

## Visual and interaction rules

Use light, quiet surfaces and one primary action per local task. Ink is text,
salmon is action/selection, and compact SVG icons identify the five views. The
live Linux desktop retains its actual browser/OS appearance. No remote font,
analytics, cloud account, provider OAuth or model/chat UI is required.

The sidebar becomes horizontal navigation on narrow screens. Panels stack,
configuration and instructions wrap, and keyboard focus remains visible. Polling
preserves skill search and focused list items when data is unchanged. Connection,
authorization, recording and interrupted states derive from the runtime. Owner
access failures explain the CLI recovery without exposing the existing host PC.

The practice task is a local form in the real guest browser, styled with the same
Sendtry palette. It demonstrates Teach and profile persistence offline; its
browser-local saved note is not a second workflow backend.

## Current boundaries

Portable host CLI does not mean portable guest OS. The implemented computer is a
Docker Linux guest; macOS/Windows native control or isolated VM guests require
separate adapters and explicit permissions. See [support](../README.md#platform-support),
[security](../SECURITY.md) and [validation](VALIDATION.md).

Teaching records bounded main-frame browser events plus file/terminal markers.
It is not universal desktop capture or video. Users can review instructions,
export a completed skill and reuse it through a harness. Skill editing/import,
archives and automatic replay are future work, not empty controls in the console.
